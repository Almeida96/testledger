TestLedger now discovers intermittent outcomes across a branch without requiring
an agent to know each test ID first.

Use the new `test_stability` MCP tool or `stability --run RUN_ID`. The query scans
up to 50 runs ending at the selected head and returns ranked candidates, cited
timelines, retry signals, and counts for tests with short histories. Tests absent
from the head remain discoverable.

Missing, skipped, and equal-time observations do not create transitions. Passes
after reported retry failures are identified separately. Same-commit transition
counts provide context without claiming that the environment was unchanged.
A snapshot guard detects changed run selections between pages.

Download `testledger-0.3.0.zip`, extract it, and run `bin/testledger --help`
(`bin/testledger.bat` on Windows). Java 21 or later is required. SHA-256 checksums
are included. Existing 0.1.0 and 0.2.0 databases need no migration.

The archive includes `docs/stability.md` and a reproducible offline MCP demo.
JUnit coverage includes every four-run combination of pass, failure, error,
skip, and absence. Independent MCP/CLI tests check evidence, pagination, backfills,
and read-only behavior on Linux and Windows before publication.

These signals guide investigation. They do not prove flakiness, identify a root
cause, or automatically quarantine tests.

TestLedger can now investigate slower tests as well as failures.

The new `performance_regressions` MCP tool compares each eligible head testcase
against a median from older runs in the same branch. Results include thresholds,
coverage counts, and evidence for the head and every baseline sample.

Use `timings` for JSON output or `timing-check` in CI. The gate returns separate
exit codes for regressions and insufficient history, so a fresh ledger cannot
silently pass as stable. Both absolute and percentage thresholds must be met.

Failed, skipped, retried, and unmeasured observations are excluded. A snapshot
guard detects baseline changes between result pages. Existing 0.1.0 databases
remain readable without migration.

Download `testledger-0.2.0.zip`, extract it, and run `bin/testledger --help`
(`bin/testledger.bat` on Windows). Java 21 or later is required. SHA-256 checksums
are included. See `docs/timing-analysis.md` in the archive for CI examples and
the coverage contract, and run `pnpm demo` after installing development dependencies
to reproduce the synthetic MCP investigation.

JUnit and independent MCP/CLI tests run on Linux and Windows before publication.
Timing increases are diagnostic signals; runner load and environment changes can
also explain them. This release makes no claim of a controlled benchmark or
live-model diagnosis.
